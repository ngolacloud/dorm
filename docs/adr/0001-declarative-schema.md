# ADR 0001 — a declarative `dorm.schema`, compiled to Rust

Status: accepted · 2026-10-28

## Context

DORM began as a pure compile-time ORM: models are Rust structs annotated with
`#[derive(Model)]`. That gives typed queries and zero-overhead access, but it is
unfamiliar to developers coming from Prisma (a declarative `schema.prisma`) or
Django (declarative model classes), and it has no single artefact to point
tooling — `generate`, `db pull`, `format`, `api` — at.

## Decision

Adopt a **Prisma-style declarative schema**, `dorm.schema`, as the single source
of truth, and **compile it to Rust** rather than interpret it at runtime:

- `dorm.schema` uses Prisma-faithful syntax (`datasource`, `model`, `@id`,
  `@default`, `@relation`, `@db.VarChar`, `Model[]` back-relations).
- `dorm generate` turns it into `src/models.rs` — ordinary `#[derive(Model)]`
  structs — with a `// @generated … do not edit by hand` header.
- The generated Rust is **not** hand-edited; you edit the schema and regenerate.
- The models remain compile-time typed, so queries and performance are
  unchanged: the declarative ergonomics are a front end, not a runtime engine.

This reconciles the three goals the brief set: Prisma's declarative schema +
tooling, Django's entity feel, and Rust's compile-time performance and safety.

### Why compile, not interpret

A runtime schema engine (Prisma's model) would forfeit the typed query API and
the zero-overhead access that are DORM's reason to exist, and could not offer
Rust's compile-time guarantees. "The highest performance a market ORM reaches"
is only possible by generating code the Rust compiler then optimises. The schema
is therefore a *source* that `dorm generate` compiles, exactly as `.proto` or a
GraphQL SDL is compiled, not a document read on every request.

### Consequences

- `dorm init` writes a `dorm.schema` and the generated `src/models.rs`;
  `dorm new model` appends a `model` block to the schema, not to the Rust.
- The generated file is committed (so `cargo build` works without a generate
  step) but regenerated by `dorm generate`; CI can check it is up to date.
- `db pull` (introspect → schema), `format` (pretty-print the schema) and
  `api generate` (Axum + OpenAPI over the models) now have a clear input.
- Writing Rust models by hand still works — the derive is unchanged — but the
  documented, tooled path is the schema.

## Scope of v0.1 (what `dorm generate` supports today)

See [../schema.md](../schema.md). Scalars, `@id @default(autoincrement())` →
BIGSERIAL, `@default(now())`/`@updatedAt`, `@db.VarChar(n)`, `@unique`/`@index`,
to-one `@relation(onDelete:)` and `Model[]` back-relations, `@@map`/`@map`,
nullable `?`. Not yet: composite keys, `@@unique`/`@@index` emission,
table-level checks, enums, multi-file schemas. These are additive and tracked in
[../roadmap.md](../roadmap.md).

## `dorm api` (planned, this ADR's corollary)

`dorm api generate` will generate an Axum service + an OpenAPI document over the
models — generated code, staying in the ORM context, so it inherits the
compile-time performance. It is specified here and in the roadmap but **not yet
built**; it is not shipped empty.
